# Rule 1 - 成功時回報 US 全綠摘要

- Level: `MUST`
- 成功結束時必須回報：`layer`、`plan-package`、US 識別、本 US 已綠的 Scenario／測檔清單、使用的全套跑測指令、終態全套為綠的摘要、主要改動的程式路徑（高階即可）。
- 若迴圈中曾有附帶變綠，應在已綠清單或摘要中註明（與本輪鎖定目標區分）。
- 不負責勾選 `task-*.md` checkbox。

## Good Example

- 這個例子是好的，因為 implement 能接續 Refactor，且附帶變綠有交代。

```text
US: US-1
greened: S-1-1…S-1-5（S-1-3 於 S-1-1 輪附帶變綠）
command: npm test（backend/）
result: 本 US 全綠；本層既有綠仍綠
touched: src/routes/albums.js, src/routes/photos.js
```

## Bad Example

- 這個例子是壞的，因為只說「好了」並代勾 task。

```text
Green 完成。（並勾 task-backend checkbox）
```

# Rule 2 - 失敗時回報卡點與仍紅清單

- Level: `MUST`
- 失敗時必須回報卡點類型（缺輸入、範圍無法收斂、環境洞、回歸弄紅既有綠、無法推進的仍紅 Scenario 等）、**本輪鎖定目標 Scenario ID**、仍紅清單、以及建議 implement 下一步。

## Good Example

- 這個例子是好的，因為仍紅、本輪目標與回歸分開寫清。

```text
卡點: 回歸
本輪目標: S-1-2
弄紅: US-2 的 s-2-1（先前已綠）
仍紅: S-1-2（US-1 尚有仍紅但不可交付）
請修復回歸後重呼 /tdd-e2e-green
```

## Bad Example

- 這個例子是壞的，因為失敗原因不可操作。

```text
有的過有的不過，你再看看
```

# Rule 3 - 環境洞只交接、不代修

- Level: `MUST`
- 環境／基建缺口停止並交回 implement，不在 Green 呼叫中擴大做環境 setup。

## Good Example

- 這個例子是好的，因為只交接。

```text
卡點: 環境洞 — 無 scripts.test → 交回 implement
```

## Bad Example

- 這個例子是壞的，因為 Green 順便重做環境建立章節。

```text
自己 npm init、裝依賴、寫測試腳本後繼續 Green
```
