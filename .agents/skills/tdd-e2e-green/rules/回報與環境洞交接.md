# Rule 1 - 成功時回報本則已綠摘要

- Level: `MUST`
- 成功結束時必須回報：`layer`、`plan-package`、本則 ID、已綠的測檔、使用的全套跑測指令、終態本則為綠且既有綠仍綠、主要改動的程式路徑（高階即可）。
- 若有附帶變綠的其他測，可列出但須標明「非本則目標」。
- 不負責勾選 `task-*.md` checkbox。

## Good Example

- 這個例子是好的，因為 implement 能接續本則 Refactor。

```text
本則: S-1-1
greened: s-1-1-create-album.test.js
command: npm test（frontend/）
result: 本則已綠；既有綠仍綠
touched: src/index.js（建立表單）
附帶變綠: 無
```

## Bad Example

- 這個例子是壞的，因為只說「好了」並代勾 task，或回報成 US 全綠。

```text
本 US 全綠。（並勾 task-frontend checkbox）
```

# Rule 2 - 失敗時回報卡點與本則仍紅

- Level: `MUST`
- 失敗時必須回報卡點類型（缺輸入、本則測找不到、環境洞、回歸弄紅既有綠、無法讓本則變綠、踩到本則不驗證等）、本則是否仍紅、以及建議 implement 下一步。

## Good Example

- 這個例子是好的，因為回歸與本則分開寫清。

```text
卡點: 回歸
弄紅: 先前已綠的 s-2-1
本則: S-1-1 已綠但不可交付
請修復回歸後重呼 /tdd-e2e-green
```

## Bad Example

- 這個例子是壞的，因為失敗原因不可操作。

```text
有的過有的不過，你再看看
```

# Rule 3 - 環境洞只交接、不代修

- Level: `MUST`
- 環境／基建缺口停止並交回 implement，不在 Green 呼叫中擴大做環境 setup。

## Good Example

- 這個例子是好的，因為只交接。

```text
卡點: 環境洞 — 無 scripts.test → 交回 implement
```

## Bad Example

- 這個例子是壞的，因為 Green 順便重做環境建立章節。

```text
自己 npm init、裝依賴、寫測試腳本後繼續 Green
```
