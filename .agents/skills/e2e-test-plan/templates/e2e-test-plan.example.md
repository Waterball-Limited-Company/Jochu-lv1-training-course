## 後端

後端 Scenario 從正式 API 進入真實後端，使用可重置測試資料，並只從正式 API 回應觀測結果。

### US-1 建立相簿（優先級：P1）

#### Scenario: S-1-1 建立名為「旅行」的相簿

```gherkin
Scenario: 建立名為「旅行」的相簿
  Given 使用者尚未建立任何相簿
  When 使用者建立一個名為「旅行」的相簿
  Then 「旅行」相簿存在
```

**對應欄位**:

- **US**
  - US-1 建立相簿
- **AC / Edge**
  - AC-1-1 建立成功後可再次查到相簿
- **FR**
  - US1-FR1 系統必須允許使用者建立相簿並命名
- **受測部位**
  - `POST /albums`
- **前置資料**
  - 測試資料庫已重置，尚無相簿
- **觀測通道**
  - 建立 API 回應與重新查詢 API 的結果
- **必須維持不變**
  - 不建立額外相簿
- **本則不驗證**
  - 前端畫面與跨服務接線
- **預期 TDD Red**
  - 建立端點尚未存在，因此主斷言因 404 失敗
- **API**
  - `POST /albums` 建立相簿
- **API 契約案例**
  - `API-001-C1`

#### Scenario: S-1-2 拒絕未提供相簿名稱

```gherkin
Scenario: 拒絕未提供相簿名稱
  Given 使用者尚未建立任何相簿
  When 使用者建立相簿但未提供 name
  Then 系統回傳名稱必填錯誤，且沒有建立相簿
```

**對應欄位**:

- **US**
  - US-1 建立相簿
- **AC / Edge**
  - Edge-1-1 相簿名稱為必填
- **FR**
  - US1-FR1 系統必須允許使用者建立相簿並命名
- **受測部位**
  - `POST /albums`
- **前置資料**
  - 測試資料庫已重置，尚無相簿
- **觀測通道**
  - 建立 API 錯誤回應與重新查詢 API 的結果
- **必須維持不變**
  - 相簿數量維持為零
- **本則不驗證**
  - 前端錯誤呈現與跨服務接線
- **預期 TDD Red**
  - 端點尚未驗證缺少名稱，因此主斷言收到非 400 回應
- **API**
  - `POST /albums` 拒絕缺少 name
- **API 契約案例**
  - `API-001-C2`

## 前端

前端瀏覽器端對端測試套件：Playwright
測試開啟真實執行期頁面，並以 `api-plan.md` 的 `API-001-C1`、`API-001-C2` 建立 API Mock；本層不啟動真實後端。

### US-1 建立相簿（優先級：P1）

#### Scenario: S-1-1 建立名為「旅行」的相簿

```gherkin
Scenario: 建立名為「旅行」的相簿
  Given 使用者已開啟相簿首頁
  When 使用者輸入「旅行」並送出建立
  Then 畫面顯示「旅行」相簿
```

**對應欄位**:

- **US**
  - US-1 建立相簿
- **AC / Edge**
  - AC-1-1 建立成功後可看到相簿
- **FR**
  - US1-FR1 系統必須允許使用者建立相簿並命名
- **受測部位**
  - 真實執行期頁面的建立相簿流程
- **前置資料**
  - API Mock 依契約回傳成功結果
- **觀測通道**
  - Playwright 觀測畫面與瀏覽器網路請求
- **狀態／畫面文案**
  - 建立成功後顯示「旅行」
- **必須維持不變**
  - 頁面其餘相簿不消失
- **本則不驗證**
  - 真實後端與資料庫持久化
- **預期 TDD Red**
  - 建立控制項尚未存在，因此找不到送出按鈕
- **UI**
  - 輸入相簿名稱並送出後顯示新相簿
- **API**
  - API Mock 攔截 `POST /albums`
- **API 契約案例**
  - `API-001-C1`

#### Scenario: S-1-2 顯示缺少名稱錯誤

```gherkin
Scenario: 顯示名稱必填錯誤
  Given 使用者已開啟相簿首頁，且 API Mock 會拒絕缺少 name 的請求
  When 使用者未填相簿名稱就送出
  Then 畫面顯示「name is required」，且沒有新增相簿
```

**對應欄位**:

- **US**
  - US-1 建立相簿
- **AC / Edge**
  - Edge-1-1 相簿名稱為必填
- **FR**
  - US1-FR1 系統必須允許使用者建立相簿並命名
- **受測部位**
  - 真實執行期頁面的建立失敗流程
- **前置資料**
  - API Mock 依 API-001-C2 對缺少 name 的請求回傳 400 錯誤
- **觀測通道**
  - Playwright 觀測錯誤文案、相簿清單與瀏覽器網路請求
- **狀態／畫面文案**
  - `name is required`
- **必須維持不變**
  - 相簿清單不新增資料
- **本則不驗證**
  - 真實後端與資料庫驗證
- **預期 TDD Red**
  - 頁面尚未處理 400 錯誤，因此找不到錯誤文案
- **UI**
  - 未填名稱送出後顯示 API 錯誤
- **API**
  - API Mock 攔截 `POST /albums` 並回傳 400
- **API 契約案例**
  - `API-001-C2`

## 整合

整合驗收停用所有 Mock，從真實瀏覽器串接真實執行期前端、正式 API、真實後端與可重置測試資料。

### US-1 建立相簿（優先級：P1）

#### Scenario: US-1 由瀏覽器建立相簿並持久保存

```gherkin
Scenario: 由瀏覽器建立相簿並持久保存
  Given 完整系統已啟動且測試資料已重置
  When 使用者在相簿首頁建立「旅行」並重新整理
  Then 畫面仍顯示「旅行」相簿
```

**對應欄位**:

- **US**
  - US-1 建立相簿
- **受測部位**
  - 瀏覽器到可重置測試資料的完整串接
- **前置資料**
  - 前後端 US-1 完成閘門皆已通過，可重置測試資料已完成重置
- **觀測通道**
  - 真實瀏覽器畫面、正式 API 網路請求與重新整理後資料
- **必須維持不變**
  - 整合環境不連到正式資料
- **本則不驗證**
  - US-1 以外的需求
- **前端**
  - 真實執行期頁面
- **Mock**
  - 停用
- **API**
  - 正式 API
- **後端**
  - 真實後端
- **API 契約案例**
  - `API-001-C1`
