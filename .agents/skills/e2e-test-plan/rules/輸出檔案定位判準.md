# Rule 1 - 最終 e2e-test-plan 必須寫到固定路徑

- Level: `MUST`
- `e2e-test-plan` 的最終產物路徑固定為 `specs/<NNN-plan-package>/e2e-test-plan.md`。
- 不可寫入 `system-analyze/` 子目錄，也不可把完成稿只留在聊天訊息或任意檔名中。

## Good Example

- 這個例子是好的，因為輸出與同 package 的 `spec.md` 並列。

```text
specs/001-photo-albums/e2e-test-plan.md
```

## Bad Example

- 這個例子是壞的，因為把端對端測試計畫塞進 system-analyze，與本 skill 契約不符。

```text
specs/001-photo-albums/system-analyze/e2e-test-plan.md
```

# Rule 2 - `plan-package` 必須與上游 spec 目錄對齊

- Level: `MUST`
- `plan-package` 必須沿用同功能的 `specs/<NNN-plan-package>/` 目錄名，採 `NNN-` 三位數前綴加英文小寫 kebab-case slug。
- 若使用者已指定既有 package，應寫入該 package，不可另開平行目錄。

## Good Example

- 這個例子是好的，因為 e2e-test-plan 與 spec／api-plan／ui-plan 落在同一 package。

```text
specs/003-reading-list/spec.md
specs/003-reading-list/system-analyze/api-plan.md
specs/003-reading-list/system-analyze/ui-plan.md
specs/003-reading-list/e2e-test-plan.md
```

## Bad Example

- 這個例子是壞的，因為測試計畫與規格分散在不同 package。

```text
specs/003-reading-list/spec.md
specs/004-e2e-only/e2e-test-plan.md
```

# Rule 3 - 標題與小標必須對齊固定契約

- Level: `MUST`
- H1 固定為 `# 端對端測試計畫：{{FEATURE_NAME}}`，功能中文名與同 package 的 `spec.md` 對齊。
- 小標固定三行、分行書寫：`**功能分支**:`、`**建立日期**:`、`**狀態**:`；其中功能分支值必須以 inline code 包住，且與所在 `plan-package` 相同。
- `**建立日期**:` 使用本次產出日期（`YYYY-MM-DD`）；`**狀態**:` 第一版預設 `草稿`。

## Good Example

- 這個例子是好的，因為標題與小標可對回目錄。

```md
# 端對端測試計畫：照片相簿整理應用程式

**功能分支**: `001-photo-albums`
**建立日期**: 2026-07-22
**狀態**: 草稿
```

## Bad Example

- 這個例子是壞的，因為 metadata 格式不固定、功能分支無法對回 package。

```md
# E2E：photo albums

**功能**: albums-v2 ｜ **日期**: 2026-07-22
```

# Rule 4 - 產出前必須已有 api-plan 與 ui-plan

- Level: `MUST`
- 撰寫本計畫前，同 package 必須已存在 `system-analyze/api-plan.md` 與 `system-analyze/ui-plan.md`。
- 缺任一檔時應停止並要求先完成上游，不可腦補 API 路徑或 UI 頁面後硬寫對齊欄位。

## Good Example

- 這個例子是好的，因為上游合約齊備再產 e2e-test-plan。

```text
已存在：
- specs/001-photo-albums/system-analyze/api-plan.md
- specs/001-photo-albums/system-analyze/ui-plan.md
→ 可繼續產出 e2e-test-plan.md
```

## Bad Example

- 這個例子是壞的，因為尚無 api-plan 卻先寫後端 API 對齊。

```text
缺：system-analyze/api-plan.md
仍寫出：對應欄位 **API** 下的 endpoint 清單
```
