# Rule 1 - 每檔固定五個一級章節

- Level: `MUST`
- 每份 task 檔必須依序包含：
  1. `## 1. 規格閱讀`
  2. `## 2. 環境建立`
  3. `## 3. User Story 實作計劃`
  4. `## 4. 進度總覽`
  5. `## 5. 假設`
- 不可使用英文 `Setup` 作為 §2 標題。
- 不可另加「完成定義」類章節或逐步「預期結果」區塊。

## Good Example

- 這個例子是好的，因為章節順序與命名固定。

```md
## 1. 規格閱讀
## 2. 環境建立
## 3. User Story 實作計劃
## 4. 進度總覽
## 5. 假設
```

## Bad Example

- 這個例子是壞的，因為用英文 Setup，且夾了完成定義章節。

```md
## 2. Setup Phase
## 5. 後端完成定義
## 6. 假設
```

# Rule 2 - User Story 階層固定為 AC／Edge → Red → Green → Refactor

- Level: `MUST`
- §3 下每個 User Story 使用 `### US-n …（優先級：Pn）`。
- 每個 US 必須依序有 `#### AC / Edge`、`#### Red`、`#### Green`、`#### Refactor`。
- 一個 US 一輪 Red → Green → Refactor；完成後再進入下一個 US。
- Red 可列多個 Scenario，但都必須掛在該 US 的 Red 底下。

## Good Example

- 這個例子是好的，因為 US 內階層完整。

```md
### US-1 建立相簿並整理照片（優先級：P1）
#### AC / Edge
#### Red
#### Green
#### Refactor
```

## Bad Example

- 這個例子是壞的，因為先做完整包 Red 再整包 Green，或缺少 AC／Edge。

```md
### Red（全部 US）
### Green（全部 US）
```

# Rule 3 - Red／Green 必須使用巢狀「實作計畫」條列

- Level: `MUST`
- 每個 **Scenario** 的 Red checkbox 形狀為：`/tdd-e2e-red` — `S-n-m` 標題：底下 `- 實作計畫：` 再巢狀條列。
- Green checkbox 形狀為：`/tdd-e2e-green` — …：底下 `- 實作計畫：` 再巢狀條列。
- Refactor 可為單行 checkbox（可含簡短整理方向），不強制再包一層「實作計畫」。
- 進度總覽表必須能對齊該層 Red 所列 **Scenario ID**（不含下方固定驗紅項）。

## Good Example

- 這個例子是好的，因為 Scenario Red／Green 都用巢狀實作計畫。

```md
- [ ] `/tdd-e2e-red` — S-1-1 …:
  - 實作計畫：
    - …
- [ ] `/tdd-e2e-green` — 讓本 US 既有 Red 全綠:
  - 實作計畫：
    - …
```

## Bad Example

- 這個例子是壞的，因為把意圖塞成超長單行，或只用「實作意圖」標籤。

```md
- [ ] `/tdd-e2e-red` — S-1-1 …：一長串 API 與步驟擠在同一行
實作意圖：
- …
```

# Rule 4 - 每個 US 的 Red 區塊末尾必須有固定驗紅項目

- Level: `MUST`
- 在該 US `#### Red` 底下、所有 Scenario 的 `/tdd-e2e-red` 項目之後，必須再有**恰好一條**固定項目，且必須是該 Red 區塊的最後一項：
  - `- [ ] `/tdd-e2e-red` — 執行本 User Story 的測試，確認本 US 的 TDD E2E Red 測試皆已實作且皆為紅燈`
- 此項**不**掛巢狀「實作計畫」，也**不**對應某個 `S-n-m`。
- 不可把這句塞進各個 Scenario 的「實作計畫」最後一條；也不可省略或改寫語意。

## Good Example

- 這個例子是好的，因為 Scenario 做完後，Red 區塊以固定驗紅項收尾。

```md
#### Red
- [ ] `/tdd-e2e-red` — S-1-1 …:
  - 實作計畫：
    - …
- [ ] `/tdd-e2e-red` — S-1-2 …:
  - 實作計畫：
    - …
- [ ] `/tdd-e2e-red` — 執行本 User Story 的測試，確認本 US 的 TDD E2E Red 測試皆已實作且皆為紅燈
```

## Bad Example

- 這個例子是壞的，因為把驗紅寫進每個 Scenario 的實作計畫，或漏掉獨立收尾項。

```md
- [ ] `/tdd-e2e-red` — S-1-1 …:
  - 實作計畫：
    - …
    - 執行本 User Story 的測試，確認本 US 的 TDD E2E Red 測試皆已實作且皆為紅燈
```
