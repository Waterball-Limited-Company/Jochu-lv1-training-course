# Rule 1 - 每檔固定五個一級章節

- Level: `MUST`
- 每份 task 檔必須依序包含：
  1. `## 1. 規格閱讀`
  2. `## 2. 環境建立`
  3. `## 3. User Story 實作計劃`
  4. `## 4. 進度總覽`
  5. `## 5. 假設`
- 不可使用英文 `Setup` 作為 §2 標題。
- 不可另加「完成定義」類章節或逐步「預期結果」區塊。

## Good Example

- 這個例子是好的，因為章節順序與命名固定。

```md
## 1. 規格閱讀
## 2. 環境建立
## 3. User Story 實作計劃
## 4. 進度總覽
## 5. 假設
```

## Bad Example

- 這個例子是壞的，因為用英文 Setup，且夾了完成定義章節。

```md
## 2. Setup Phase
## 5. 後端完成定義
## 6. 假設
```

# Rule 2 - User Story 下是 AC／Edge，再按則展開一區塊 RGB

- Level: `MUST`
- §3 下每個 User Story 使用 `### US-n …（優先級：Pn）`。
- 每個 US 必須先有 `#### AC / Edge`，接著依該 US 在本層的 Scenario **各開一個區塊**。
- 後端／前端區塊標題為 `#### S-n-m <標題>`；整合區塊標題為 `#### US-n <標題>`。
- 每個區塊內必須依序有三個 checkbox：`/tdd-e2e-red` → `/tdd-e2e-green` → `/tdd-e2e-refactor`。
- 不可使用 US 級 `#### Red`、`#### Green`、`#### Refactor` 把多則 Scenario 收成三大段。
- 一則 Scenario 做完 Red → Green → Refactor 後，才進入下一則；不可一個 US 先整包 Red 再整包 Green。

## Good Example

- 這個例子是好的，因為 AC／Edge 之後每則各自一區塊 RGB。

```md
### US-1 建立相簿並整理照片（優先級：P1）

#### AC / Edge

- AC-1-1 …

#### S-1-1 建立名為「旅行」的相簿

- [ ] `/tdd-e2e-red` — S-1-1 建立名為「旅行」的相簿:
  - 受測行為：
    - …
- [ ] `/tdd-e2e-green` — S-1-1:
  - 實作計畫：
    - …
- [ ] `/tdd-e2e-refactor` — S-1-1:
  - 整理範圍：
    - …
```

## Bad Example

- 這個例子是壞的，因為用 US 級三大段把多則 Scenario 收成一輪。

```md
### US-1 建立相簿並整理照片（優先級：P1）
#### AC / Edge
#### Red
- [ ] `/tdd-e2e-red` — S-1-1 …
- [ ] `/tdd-e2e-red` — S-1-6 …
#### Green
#### Refactor
```

# Rule 3 - Red／Green／Refactor 各自用固定巢狀標籤

- Level: `MUST`
- 每個區塊的 Red checkbox 形狀為：`/tdd-e2e-red` — `<ID> <標題>`：底下 `- 受測行為：` 再巢狀條列。
- Green checkbox 形狀為：`/tdd-e2e-green` — `<ID>`：底下 `- 實作計畫：` 再巢狀條列。
- Refactor checkbox 形狀為：`/tdd-e2e-refactor` — `<ID>`：底下 `- 整理範圍：` 再巢狀條列。
- `<ID>` 後端／前端為 `S-n-m`，整合為 `US-n`，且必須與區塊標題同一則。
- 進度總覽表必須能對齊該層所列 **Scenario ID**（後端／前端 `S-n-m`，整合 `US-n`）。
- 不可在 Red 末尾另加 US 級驗紅項，也不可把 Green 寫成「讓本 US 既有 Red 全綠」。

## Good Example

- 這個例子是好的，因為三個 checkbox 的巢狀標籤分流，且沒有 US 級驗紅項。

```md
- [ ] `/tdd-e2e-red` — S-1-1 建立名為「旅行」的相簿:
  - 受測行為：
    - 前置：尚未有任何相簿
    - 打：主頁建立相簿表單
    - 看：執行期主頁
    - 期望：主頁看得到「旅行」
    - 還沒做時：看不到「旅行」
- [ ] `/tdd-e2e-green` — S-1-1:
  - 實作計畫：
    - 主頁建立表單 → `POST /albums` → 執行期主頁出現「旅行」
    - 本則不驗證：批次匯入
- [ ] `/tdd-e2e-refactor` — S-1-1:
  - 整理範圍：
    - 在綠燈下整理剛寫的建立表單
    - 不准擴到批次匯入
```

## Bad Example

- 這個例子是壞的，因為 Red 用「實作計畫」、Green 一次綠整包 US，或 Red 末尾掛驗紅項。

```md
- [ ] `/tdd-e2e-red` — S-1-1 …：一長串 API 與步驟擠在同一行
  - 實作計畫：
    - …
- [ ] `/tdd-e2e-green` — 讓本 US 既有 Red 全綠:
  - 實作計畫：
    - …
- [ ] `/tdd-e2e-red` — 執行本 User Story 的測試，確認本 US 的 TDD E2E Red 測試皆已實作且皆為紅燈
```
