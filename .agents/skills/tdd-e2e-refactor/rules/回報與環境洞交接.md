# Rule 1 - 成功時回報整理摘要與本則仍綠

- Level: `MUST`
- 成功時回報：本則 ID、執行的整理項、主要觸碰路徑、全套跑測指令、終態本則仍綠且既有綠仍綠。
- 不代勾 `task-*.md` checkbox。

## Good Example

- 這個例子是好的，因為 implement 可接續下一則 Red。

```text
本則: S-1-1
done: 去重建立表單命名
touched: src/index.js
command: npm test → S-1-1 PASS
```

## Bad Example

- 這個例子是壞的，因為無證明卻稱完成。

```text
重構好了（沒跑測）
```

# Rule 2 - 失敗時回報卡點

- Level: `MUST`
- 失敗時回報：本則起點非綠、重構後無法恢復綠、踩到不准擴到的下一則、環境洞、缺輸入等，並說明已回退或現況。

## Good Example

- 這個例子是好的，因為說明已回退。

```text
卡點: 重構後 s-1-1 紅；已回退抽取變更；本則恢復綠
請調整整理範圍後重呼
```

## Bad Example

- 這個例子是壞的，因為留下紅燈離開。

```text
重構到一半變紅，之後再修
```

# Rule 3 - 環境洞交回 implement

- Level: `MUST`
- 環境／基建缺口停止並交回 implement，不擴大做環境 setup。

## Good Example

- 這個例子是好的，因為只交接。

```text
找不到 test script → 交回 implement
```

## Bad Example

- 這個例子是壞的，因為 Refactor 去改環境腳本契約。

```text
自己重寫 package.json test 腳本當重構的一部分
```
