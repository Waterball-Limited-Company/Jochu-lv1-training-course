# Rule 1 - 起點本則已綠，終點本則仍綠

- Level: `MUST`
- 進入重構前：本則測必須為綠，且本層既有綠燈仍綠。若本則仍紅，不得開始 Refactor，應回報先完成 `/tdd-e2e-green`。
- 不要求尚未寫出的下一則、或「本則不驗證」列出的測也綠。
- 結束時本則必須仍綠、既有綠仍綠；過程變紅必須修回或回退，不可帶紅交付。

## Good Example

- 這個例子是好的，因為 S-1-1 綠了就整理，不等人家 S-1-6。

```text
before: S-1-1 PASS（尚無 S-1-6 測）
refactor…
after: S-1-1 仍 PASS
```

## Bad Example

- 這個例子是壞的，因為本則還紅，或硬等整個 US 全綠才開始。

```text
S-1-1 仍 FAIL → 先重構目錄再說
等 S-1-1～S-1-6 全 PASS 才 Refactor
```

# Rule 2 - 完成條件對齊整理範圍且行為不變

- Level: `MUST`
- 完成條件：整理範圍列出的項目已處理（或明確回報何者無法做與原因），且本則仍綠、未改契約／驗收語意。
- 不要求「完美架構」；以該格整理範圍為準，避免無限重構。

## Good Example

- 這個例子是好的，因為範圍兩項都做完且仍綠。

```text
整理範圍: 去重建立表單命名、抽出錯誤處理
→ 兩項完成 + S-1-1 PASS
```

## Bad Example

- 這個例子是壞的，因為範圍沒寫卻持續大改。

```text
範圍只寫去重，卻重寫整個前端並宣稱還能更好
```
