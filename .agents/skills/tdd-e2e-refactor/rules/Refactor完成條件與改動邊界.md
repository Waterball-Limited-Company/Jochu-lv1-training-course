# Rule 1 - 起點與終點都必須全綠

- Level: `MUST`
- 進入重構前該層全套測試必須為綠；若起點已紅，不得開始 Refactor，應回報先完成 `/tdd-e2e-green`。
- 結束時該層全套測試必須仍為綠；過程變紅必須修回或回退，不可帶紅交付。

## Good Example

- 這個例子是好的，因為重構前後全套皆 PASS。

```text
before: npm test PASS
refactor…
after: npm test PASS
```

## Bad Example

- 這個例子是壞的，因為起點還有本 US 紅測就開始重構。

```text
S-1-4 仍 FAIL → 先重構目錄再說
```

# Rule 2 - 完成條件對齊實作計畫且行為不變

- Level: `MUST`
- 完成條件：實作計畫列出的整理項已處理（或明確回報何者無法做與原因），且全套仍綠、未改契約／驗收語意。
- 不要求「完美架構」；以該格計畫為準，避免無限重構。

## Good Example

- 這個例子是好的，因為計畫三項都做完且全綠。

```text
計畫: 去重資料存取、對齊錯誤形狀、抽路徑組裝
→ 三項完成 + PASS
```

## Bad Example

- 這個例子是壞的，因為計畫沒寫卻持續大改。

```text
計畫只寫去重，卻重寫整個服務層並宣稱還能更好
```
