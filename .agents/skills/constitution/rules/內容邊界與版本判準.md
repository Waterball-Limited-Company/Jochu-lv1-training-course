# Rule 1 - 憲法只寫專案級、可判定的規範

- Level: `MUST`
- 條文 MUST 是專案級約束（跨功能），且讀者能以是／否判斷是否遵守。
- 禁止寫入單一功能需求、具體 API path／單一 endpoint 業務欄位表、具體 UI 畫面欄位或單一 User Story 細節（那些屬 `specs/<package>/` 產物）。
- core 的技術約束可具體到堆疊與禁准項（例如允許的框架、是否禁 ORM）。
- skill 憲法可寫該面向的**專案級固定契約形狀**，並 SHOULD 附例子（例如所有列表查詢的分頁參數名、統一 response envelope）；這與「某個 endpoint 有哪些業務欄位」不同，後者禁止寫進憲法。
- 流程步驟、品質閘門、單一 skill 內部 SOP 慣例 MUST NOT 寫進憲法（那些屬各 skill 的 `rules/`）。

## Good Example

- 這個例子是好的，因為約束可判定且抽象層正確。

```md
- MUST：前端執行期不引入 React／Vue 等 UI framework。
- MUST：列表查詢分頁參數固定為 page 與 pageSize（並附 envelope 例子）。
```

## Bad Example

- 這個例子是壞的，因為把單一功能合約細節或流程步驟寫進憲法。

```md
- POST /api/albums 的 body 必須含 name 欄位。
- 必須先跑 specify 再跑 api-plan 再跑 implement。
```

# Rule 2 - 依檔案類型使用固定必要章節

- Level: `MUST`
- **core**（`.constitution/core.md`）正文 MUST 依序包含：`## 核心原則`、`## 技術約束`、`## 憲法規範效力`。核心原則章可為空說明（例如註明本版無額外原則），但標題不可刪。
- **skill 憲法**（`.constitution/<skill-name>.md`）正文 MUST 包含且僅以 `## 技術約束` 為必要二級標題（其下可附例子、表格、程式碼區塊）。
- 不可再要求或寫入已淘汰的 `## 流程與品質規範`。
- H1、中文 metadata 與 front matter 之後、第一個必要章節之前，MAY 有一段簡短定位說明。

## Good Example

- 這個例子是好的，因為 core 與 skill 各自章節契約正確。

```md
# core
## 核心原則
## 技術約束
## 憲法規範效力

# skill 憲法
## 技術約束
```

## Bad Example

- 這個例子是壞的，因為沿用已淘汰的流程章，或把 skill 憲法寫成四章 core 結構。

```md
## 核心原則
## 技術約束
## 流程與品質規範
## 憲法規範效力
```

# Rule 3 - 修訂時必須更新最後修訂；語意變更必須升版本

- Level: `MUST`
- 任何寫入／修訂成功後，`**最後修訂**:` MUST 更新為當日 `YYYY-MM-DD`。
- 若變更改變規範語意（新增／刪除／重寫 MUST 條文、改變技術基線），`**版本**:` MUST 遞增：不相容的原則重定義升 MAJOR；新增原則／章節或實質擴充升 MINOR；錯字、措辭澄清、不改變義務的潤飾升 PATCH（或僅更新日期且版本不變，僅限純澄清）。
- 新建時：`建立日期` 與 `最後修訂` 皆為當日；版本預設 `` `1.0.0` ``，除非使用者另行指定。

## Good Example

- 這個例子是好的，因為語意變更有升版，且更新日期。

```text
新增「禁止 ORM」MUST → 版本 1.0.0 → 1.1.0，最後修訂改為今日
只改錯字 → 最後修訂改今日，版本可維持或 +PATCH
```

## Bad Example

- 這個例子是壞的，因為改了硬性約束卻不升版、不改日期。

```text
把「禁止 ORM」改成「允許 ORM」，版本與最後修訂都不動
```

# Rule 4 - core 效力章必須保留憲法優先與維護邊界

- Level: `MUST`
- core 的 `## 憲法規範效力` MUST 表達：本規範與同目錄 skill 憲法優先於各 skill 預設慣例；衝突時以憲法為準；`core` 與 skill 憲法衝突時以 `core` 為準。
- MUST 表明本檔可由人工或 `/constitution` 維護。
- SHOULD 保留「交付向 skill 若約定讀取：有則遵守；缺檔時依專案約定警告後繼續」之類表述。
- skill 憲法不強制寫效力章；其優先關係由 core 效力章與讀取判準共同約束。

## Good Example

- 這個例子是好的，因為效力、優先序與缺檔策略清楚。

```md
## 憲法規範效力

- 本規範與同目錄各 skill 憲法，優先於各 skill 之預設慣例；衝突時以憲法為準。`core` 與 skill 憲法衝突時以 `core` 為準。
- 交付 skill 若約定讀取本檔：有則 MUST 遵守；若 `.constitution/core.md` 不存在，依專案約定警告後繼續。
```

## Bad Example

- 這個例子是壞的，因為效力章要求每次改憲法都自動改全部 skill。

```md
## 憲法規範效力

- 每次修訂 MUST 同步更新所有交付 skill 的 SOP。
```
