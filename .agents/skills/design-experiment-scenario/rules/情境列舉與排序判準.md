# Rule 1 - 必須先收斂目標進「範圍」句，再列情境可能性

- Level: `MUST`
- 產出情境清單前，必須先收斂本次實驗目標（學員要帶走什麼能力、要驗證什麼客製化槓桿），並壓成 Phase 2 主呈現的單行 `**範圍**：…`。
- 不可只丟情境標題、沒有範圍句，導致排序失去依據。
- 目標必須能回指使用者提供的課程內容，不可換成無關主題。
- 不可把獨立長段 `## 實驗目標`、課程來源、建立日期、狀態當作 Review **主呈現**必填（落盤附註可選，但不得取代改版格式）。

## Good Example

- 這個例子是好的，因為範圍句先交代槓桿，再接選項卡片。

```md
# Phase 2 (改版格式)｜加強系統分析顆粒度

**範圍**：在某一分析環節加注方法論／更細推理（改 Skill，不是抽換產物）。

### 選項 A｜加深 data-plan：實體／欄位萃取推理
...
```

## Bad Example

- 這個例子是壞的，因為直接列情境、沒有範圍／目標。

```md
1. 改成 OpenAPI
2. 改成 GraphQL
3. 加 sequence diagram
```

# Rule 2 - 情境必須是 5～10 張選項卡片，並以字母表達優先序

- Level: `MUST`
- 每一次 Phase 2 產出的可能性必須介於 5（含）到 10（含）個。
- 以 **選項 A、B、C…** 標示；**A 為最高優先**，其後依字母遞降；不可並列「同等第一」而不說明取捨。
- 不可改回優先序數字表取代卡片格式（勾選時用字母回覆）。

## Good Example

- 這個例子是好的，因為數量與字母優先序清楚。

```md
### 選項 A｜…（最推薦）
### 選項 B｜…
…
### 選項 G｜…（保底／進階）
```

## Bad Example

- 這個例子是壞的，因為只有 3 個，或沒有排序。

```md
- A 方案
- B 方案
- C 方案
```

# Rule 3 - 主呈現必須用改版格式；每張選項卡片必須含固定欄位

- Level: `MUST`
- Phase 2 對使用者的主呈現必須為改版格式：
  1. 標題：`# Phase 2 (改版格式)｜{{TOPIC}}`（或同等級標題）
  2. 單行：`**範圍**：…`
  3. 其後直接選項卡片；結尾請以字母勾選
- 每張卡片標題格式：`### 選項 X｜{{短標}}`（X 為大寫英文字母；短標可用 `加深／改／抽換 …：…` 等語感，依課綱槓桿選用）。
- 正文必須依序包含以下欄位（標題固定）：
  - `**怎麼實作**`：具體改哪些 skill／產物／步驟（不要只用抽象口號）
  - `**為何效益高**`（若語感較適合可寫「為何有效」，但語意同為效益說明）
  - `**學員瞬間看懂的點**`：一句話 Aha
  - 評分列：`實務貼近度：…｜教學清晰度：…｜工時風險：…`（星等可用 ★☆，工時風險用低／中／中高／高）
- 禁止使用「抽換什麼」作為欄位名；若情境本質是抽換，把路徑／產物變更寫進「怎麼實作」。

## Good Example

- 這個例子是好的，因為改版格式外殼與卡片欄位齊全。

```md
# Phase 2 (改版格式)｜抽換系統分析 API Artifact

**範圍**：把系統分析某類 Artifact 抽換成團隊慣用格式（改輸出契約，不是只改文案）。

### 選項 A｜API 合約：Markdown api-plan → OpenAPI

**怎麼實作**
`system-analyze/api-plan.md` → `openapi.yaml`

**為何效益高**
團隊常已有 Swagger 流程。

**學員瞬間看懂的點**
同一分析鏈，API 產物從 md 變成 OpenAPI。

實務貼近度：★★★★★｜教學清晰度：★★★★★｜工時風險：中
```

## Bad Example

- 這個例子是壞的，因為用舊企劃外殼或表格摘要取代改版格式。

```md
# 實驗目標與情境清單：…
**課程來源**: …
## 實驗目標
…

| 優先序 | 情境 | 說明 |
| 1 | OpenAPI | … |
```

# Rule 4 - 排序必須使用固定評估軸

- Level: `MUST`
- 排序至少考慮：教學效益、產物可觀測性、課堂可完成性、與客製化槓桿（憲法／改 Skill／抽換 Artifact）的對齊。
- 這些軸應反映在「為何效益高」與評分列；前三名（A～C）的效益說明不可空泛。
- 不可只依「實作最炫」或「最新技術」排序而忽略課堂可完成性。

## Good Example

- 這個例子是好的，因為理由對齊評估軸。

```md
**為何效益高**
可觀測、對齊抽換 Artifact、課堂可在單次完成 Prompt＋三跑。
```

## Bad Example

- 這個例子是壞的，因為理由無法支撐排序。

```md
**為何效益高**
比較完整。
```

# Rule 5 - 清單必須停在勾選，不可擅自當成課堂定案

- Level: `MUST`
- Phase 2 產出的排序清單是候選，不是定案；必須請使用者勾選要進課堂的**選項字母**。
- 未獲勾選確認前，不可自行進入 Prompt 規範或實跑階段。

## Good Example

- 這個例子是好的，因為明確請使用者勾選字母。

```md
請回覆要列入課堂的選項字母（可多選），例如：`A, C`
```

## Bad Example

- 這個例子是壞的，因為直接宣布開做第一名。

```md
已選定選項 A，開始寫 Prompt。
```
