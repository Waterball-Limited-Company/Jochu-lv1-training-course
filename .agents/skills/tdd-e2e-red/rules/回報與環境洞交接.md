# Rule 1 - 成功時必須回報可接續欄位

- Level: `MUST`
- Red 階段成功時，必須在同一 Scenario Agent 脈絡保留：`scenario-agent-id`、本則 ID（與標題）、觀測通道、新測檔路徑、使用的全套跑測指令，以及下列其一：主斷言如何形成合格 Red；或既有綠燈的可還原敏感度檢查、還原後全綠證據。另記錄是否新增／調整 fixture、helper 或最小骨架。
- 不負責改寫或勾選 `task-*.md` 的 checkbox；進度勾選由 implement 處理。

## Good Example

- 這個例子是好的，因為 implement 能直接接續本則 Green。

```text
本則: S-1-1
看: 執行期主頁
主斷言: 主頁看不到「旅行」（value difference）
test: frontend/tests/s-1-1-create-album.test.js
command: npm test（於 frontend/）
skeleton: 無
```

## Bad Example

- 這個例子是壞的，因為只說「好了」且順手改 task checkbox。

```text
Red 完成。
（並把 task-frontend.md 對應 - [ ] 改成 - [x]）
```

# Rule 2 - 失敗時必須回報卡點類型與缺什麼

- Level: `MUST`
- 失敗停止時必須明確回報卡點類型與缺口。卡點類型應對齊結果五類或進場失敗，例如：缺必填輸入、本則索引失敗、Gherkin 與受測行為矛盾、未碰到主斷言、環境洞、非預期綠、測試本身不可執行且無法收斂為合格 Red。
- 環境洞必須寫清楚要 implement 補什麼，不可含糊說「環境有問題」。

## Good Example

- 這個例子是好的，因為 implement 知道要補哪一步。

```text
卡點: 未碰到主斷言
現象: 卡在登入 404，尚未看到執行期主頁有沒有「旅行」
請回到本則 Red 把斷言打到觀測通道
```

## Bad Example

- 這個例子是壞的，因為失敗原因不可操作。

```text
跑不起來，你自己看一下
```

# Rule 3 - 環境洞只交接、不代修

- Level: `MUST`
- 判定為環境／基建缺口時，本 skill 的職責是停止並交接給 implement，不在本次呼叫中擴大做環境 setup。
- 與「最小骨架」的界線以 `Red完成條件與改動邊界.md` 為準；有爭議時停止 Scenario 並由 Scenario Agent 回報 `/implement`。

## Good Example

- 這個例子是好的，因為只交接、不越權修環境。

```text
回報環境洞 → 結束本次 /tdd-e2e-red
```

## Bad Example

- 這個例子是壞的，因為 Red 順便把整段環境建立做完。

```text
發現沒有 frontend/ → 自己 mkdir、npm init、裝 vite
```
