# Rule 1 - 呼叫時必須帶齊代理與單則欄位

- Level: `MUST`
- Scenario Agent 呼叫 `/tdd-e2e-red` 時必須提供：`scenario-agent-id`、`layer`（僅 `backend`／`frontend`）、`plan-package`、`user-story`、本則 `S-n-m` ID／標題、受測行為與已定位片段。
- `scenario-agent-id` 必須與層別、User Story 與 Scenario 一致，讓 Green、Refactor 可驗證仍在同一代理脈絡。
- 受測行為必須含「看」；缺欄位或 `layer=integration` 時停止，不可猜測。

## Good Example

```text
scenario-agent-id: frontend-US-1-S-1-1
layer: frontend
plan-package: 001-photo-albums
user-story: US-1
本則: S-1-1 建立名為「旅行」的相簿
受測行為: 看＝真實瀏覽器執行期頁面
```

## Bad Example

```text
Scenario: US-1
layer: integration
請製造一個 Red
```

# Rule 2 - 一次呼叫只處理一個 Scenario

- Level: `MUST`
- 一次 `/tdd-e2e-red` 只能處理一個後端或前端 Scenario。
- 帶入多個 ID、整個 User Story 或整合 `US-n` 時必須拒絕。

## Good Example

```text
僅 S-1-1
```

## Bad Example

```text
一次寫 S-1-1～S-1-5 的 Red
```

# Rule 3 - 已定位片段優先

- Level: `MUST`
- 使用 Scenario Agent 交接的 e2e、task、系統分析與契約片段，不重新整檔載入。
- 若片段缺少本則必要欄位，只能手術式補讀同一元素；仍找不到就停止。

## Good Example

```text
交接已含 S-1-1 與 POST /albums → 直接寫測
```

## Bad Example

```text
忽略交接，重新通讀 spec、e2e、api-plan 與所有 task
```
