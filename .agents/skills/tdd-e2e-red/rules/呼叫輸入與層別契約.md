# Rule 1 - 呼叫時必須帶齊必填欄位

- Level: `MUST`
- implement 呼叫 `/tdd-e2e-red` 時必須顯式提供：`layer`（`backend`／`frontend`／`integration`）、`plan-package`（僅目錄名，如 `001-photo-albums`，**不含** `specs/` 前綴）、單一 Scenario 的 ID／標題、該格實作計畫。
- 規格路徑一律寫成 `specs/<plan-package>/...`；不可把已含 `specs/` 的字串再當 `plan-package`。
- 缺少任一必填欄位時必須停止，回報缺什麼，不可自行猜測 `layer` 或 package 路徑。

## Good Example

- 這個例子是好的，因為四項都由 implement 顯式帶入，且 `plan-package` 不含 `specs/`。

```text
layer: backend
plan-package: 001-photo-albums
Scenario: S-1-1 建立「旅行」相簿並一次匯入多格式照片
實作計畫:（巢狀條列）
→ e2e 路徑: specs/001-photo-albums/e2e-test-plan.md
```

## Bad Example

- 這個例子是壞的，因為缺少 `layer` 與 `plan-package`，卻自行推斷。

```text
Scenario: S-1-1
（自行假設後端、自行搜 specs/）
```

# Rule 2 - 一次呼叫只處理一個 Scenario

- Level: `MUST`
- 一次 `/tdd-e2e-red` 只能對應一個 Scenario（對齊 task 一格一呼叫）。
- 若 prompt 帶入多個 Scenario ID／標題，必須拒絕並回報，不可默默只做第一個或一次寫多支。

## Good Example

- 這個例子是好的，因為範圍鎖定單一 Scenario。

```text
僅 S-1-2
```

## Bad Example

- 這個例子是壞的，因為一次塞入同 US 多個 Scenario。

```text
請一次把 S-1-1～S-1-5 的 Red 都寫完
```

# Rule 3 - Scenario 定位失敗時只允許有限度搜尋

- Level: `MUST`
- 應先以 Scenario ID／標題在 `specs/<plan-package>/e2e-test-plan.md` 定位對應區塊。
- 直接定位失敗時，僅允許在**同檔**內以 ID／標題再搜一次；仍找不到必須停止並回報缺的索引，不可改搜其他規格檔或擴大到整 repo。

## Good Example

- 這個例子是好的，因為搜尋範圍仍鎖在同 package 的 e2e-test-plan。

```text
在 specs/001-photo-albums/e2e-test-plan.md 內搜 S-1-2
找不到 → 停止回報
```

## Bad Example

- 這個例子是壞的，因為索引失敗後去翻 `spec.md`／整份 task 補洞。

```text
e2e 找不到就改讀 spec.md 與整份 task-backend.md
```
