# Rule 1 - 呼叫時必須帶齊必填欄位

- Level: `MUST`
- implement 呼叫 `/tdd-e2e-red` 時必須顯式提供：`layer`（`backend`／`frontend`／`integration`）、`plan-package`（僅目錄名，如 `001-photo-albums`，**不含** `specs/` 前綴）、本則 ID／標題、該格**受測行為**。
- 本則 ID：後端／前端為 `S-n-m`；整合為 `US-n`（與 e2e `## 整合` 區塊 ID 相同，不是把整個 User Story 當範圍）。
- 受測行為必須含「看」（觀測通道）。規格路徑一律寫成 `specs/<plan-package>/...`。
- 缺少任一必填欄位時必須停止，回報缺什麼，不可自行猜測 `layer` 或 package 路徑。

## Good Example

- 這個例子是好的，因為本則與受測行為由 implement 顯式帶入，整合可用 `US-n`。

```text
layer: frontend
plan-package: 001-photo-albums
本則: S-1-1 建立名為「旅行」的相簿
受測行為: 看＝執行期主頁
```

## Bad Example

- 這個例子是壞的，因為缺少 `layer` 與本則，卻自行推斷。

```text
Scenario: S-1-1
（自行假設後端、自行搜 specs/）
```

# Rule 2 - 一次呼叫只處理一個 Scenario

- Level: `MUST`
- 一次 `/tdd-e2e-red` 只能對應一個 Scenario（整合為一個 `US-n` 區塊）。
- 若 prompt 帶入多個本則 ID，必須拒絕並回報，不可默默只做第一個或一次寫多支。

## Good Example

- 這個例子是好的，因為範圍鎖定單一本則。

```text
僅 S-1-1
整合僅 US-1
```

## Bad Example

- 這個例子是壞的，因為一次塞入同 US 多個 Scenario。

```text
請一次把 S-1-1～S-1-5 的 Red 都寫完
```

# Rule 3 - 已定位片段優先；未帶片段才允許有限度搜尋

- Level: `MUST`
- 若 implement 已帶入本則 e2e 區塊與點名 SA 片段，必須直接使用，**禁止**再打開同一批 e2e／SA 檔做新進場定位。
- 僅在未帶片段時，才以本則 ID／標題在 `specs/<plan-package>/e2e-test-plan.md` 定位對應區塊。
- 直接定位失敗時，僅允許在**同檔**內以 ID／標題再搜一次；仍找不到必須停止並回報缺的索引，不可改搜其他規格檔或擴大到整 repo。

## Good Example

- 這個例子是好的，因為已有片段就不再重讀 e2e。

```text
implement 已帶 e2e S-1-1 區塊與 ui-plan 主頁片段
→ 直接寫測，不再打開 e2e-test-plan.md
```

## Bad Example

- 這個例子是壞的，因為同一輪已定位過，Red 又把 api-plan／e2e 重讀一遍。

```text
已有片段仍 cat e2e-test-plan.md 與整份 api-plan.md
```
