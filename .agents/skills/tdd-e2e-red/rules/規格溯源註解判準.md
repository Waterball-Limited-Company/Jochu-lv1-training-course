# Rule 1 - 測檔必須寫資料夾名稱／US 編號與名稱，可多行

- Level: `MUST`
- 每支新寫或修正的 E2E 測檔，必須在檔案上方（或該 US 測區塊上方）寫溯源註解。
- 格式固定為 `資料夾名稱 / US-N (US名稱)`：資料夾名稱等於本次 `plan-package`，不加 `specs/` 前綴；`US-N` 與名稱對齊 `e2e-test-plan.md` 該 Scenario 所屬 US。
- 同一測檔涵蓋多個 US 時，每個 US 各寫一行，不得合併成一句。
- 不為了寫這行註解去讀 `spec.md`。

## Good Example

- 這個例子是好的，因為一行就能從測檔對回規格資料夾與 US。

```js
// 001-photo-albums / US-1 (建立相簿並整理照片)
```

## Bad Example

- 這個例子是壞的，因為用了縮寫、加了 `specs/`，也沒有 US 名稱。

```js
// specs/001 / US1
```

# Rule 2 - 測檔註解只指到 US，不寫 FR、SC、來源或規格改動

- Level: `MUST`
- 測檔註解只承擔「這則測試對應哪份規格的哪個 US」。
- 不得在註解複製 FR／SC 全文、Redmine、使用者原話或規格改動階層。
- 不得把溯源寫進 `e2e-test-plan.md` 來代替測檔註解。

## Good Example

- 這個例子是好的，因為複數 US 就複數行，每行仍只指到 US。

```js
// 005-remove-hide-completed / US-1 (已完成卡片一律可見且固定在下方)
// 005-remove-hide-completed / US-2 (完成與取消完成維持可用)
```

## Bad Example

- 這個例子是壞的，因為把規格改動整段塞進測檔。

```js
// 刪除 002-todo-list US4 FR-010 SC-004；Redmine #12345
```
