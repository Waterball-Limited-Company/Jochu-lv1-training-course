# Rule 1 - 無 skill 引用的步驟親自執行

- Level: `MUST`
- `task-*.md` 中未標示 `/tdd-e2e-red`／`/tdd-e2e-green`／`/tdd-e2e-refactor` 的 checkbox 步驟（例如 §1 規格閱讀、§2 環境建立、驗證指令），必須由 `/implement` 親自執行。
- 不可把這類步驟丟給 tdd skill，也不可只口頭說「已完成」卻未實際執行。

## Good Example

- 這個例子是好的，因為環境步驟由 implement 落地。

```text
- [ ] 建立 backend/ 骨架 → implement 執行 mkdir／驗證
```

## Bad Example

- 這個例子是壞的，因為把環境建立塞進 `/tdd-e2e-red`。

```text
呼叫 red 時順便請它 npm init
```

# Rule 2 - TDD 步驟在同一輪執行，傳本則與已定位片段

- Level: `MUST`
- 步驟文字含 `/tdd-e2e-red`／`/tdd-e2e-green`／`/tdd-e2e-refactor` 時，在**同一輪**執行對應 skill 的 SOP，**不**為每個 checkbox 新開 Agent。
- 三格都傳：`layer`、`plan-package`、本則 ID／標題、該格巢狀內容、本 US 已定位的 e2e／SA／task 片段。
- 本則 ID：後端／前端為 `S-n-m`；整合為區塊 `US-n`。Green／Refactor **不**傳整個 User Story 當工作範圍。
- Red 傳該格「受測行為」；Green 傳該格「實作計畫」（含本則不驗證）；Refactor 傳該格「整理範圍」。
- 缺參數不得執行；應停止並回報。

## Good Example

- 這個例子是好的，因為同一輪跑 S-1-1 Red，只帶這一則與已定位片段。

```text
同一輪執行 /tdd-e2e-red SOP
layer=frontend
plan-package: 001-photo-albums
本則: S-1-1 建立名為「旅行」的相簿
受測行為:（該格巢狀）
已定位片段: e2e S-1-1 區塊、ui-plan 主頁建立表單、api-plan POST /albums
```

## Bad Example

- 這個例子是壞的，因為每格新開 Agent，或 Green 把整個 US 傳下去。

```text
新開 Agent → /tdd-e2e-green
US: US-1
請把本 US 既有 Red 全綠
```

# Rule 3 - 一個 US 只定位一次規格；內圈按則 RGB

- Level: `MUST`
- 進入某 US 的第一格 RGB 時，定位並載入該層該 US 的 e2e 區塊、點名 SA 片段與 task 該 US 區塊；這是本 US **唯一一次**規格定位。
- 同 US 後續 Red／Green／Refactor 必須沿用已定位片段，不可再當新進場重讀同一批 e2e／SA。
- 內圈順序跟 task checkbox：一則 Red → Green → Refactor，再下一則（例如 S-1-1 整圈後才 S-1-6）。
- 若對應 tdd skill SOP 仍去重開規格檔定位同一批片段，改由 implement 在本輪親自跑完該則內圈，不要再新開呼叫。

## Good Example

- 這個例子是好的，因為 US-1 只定位一次，然後 S-1-1 跑完 RGB 才進 S-1-6。

```text
US-1 首次：定位 e2e／SA／task 區塊
S-1-1 Red → Green → Refactor（沿用片段）
S-1-6 Red → Green → Refactor（沿用片段）
```

## Bad Example

- 這個例子是壞的，因為每個 checkbox 都重新定位 api-plan／e2e，或先做完整包 Red 再整包 Green。

```text
S-1-1 Red 新進場重讀 e2e＋SA
S-1-6 Red 再重讀同一批
然後一次 Green 把 US-1 全綠
```

# Rule 4 - 執行順序跟 task 文件，不跳著做

- Level: `MUST`
- 單一層內從第一個未勾選 checkbox 往下依序執行；完成一個再下一個。
- 多層時依進場選定順序，完成當層可執行範圍後再進下一層。
- 不可為求快而跳過未勾的 §1／§2 直接做 §3（除非該項已勾選）。

## Good Example

- 這個例子是好的，因為先做未勾的環境項再進第一則 Red。

```text
未勾: §2.1 → 先做完並勾選 → 再做 S-1-1 Red
```

## Bad Example

- 這個例子是壞的，因為 §2 未做完就呼叫一排 Red。

```text
環境未勾 → 直接跑 S-1-1…S-1-5 Red
```
