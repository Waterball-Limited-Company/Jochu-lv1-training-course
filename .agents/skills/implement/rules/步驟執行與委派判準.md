# Rule 1 - 無 skill 引用的步驟親自執行

- Level: `MUST`
- `task-*.md` 中未標示 `/tdd-e2e-red`／`/tdd-e2e-green`／`/tdd-e2e-refactor` 的 checkbox 步驟（例如 §1 規格閱讀、§2 環境建立、驗證指令），必須由 `/implement` 親自執行。
- 不可把這類步驟丟給 tdd skill，也不可只口頭說「已完成」卻未實際執行。

## Good Example

- 這個例子是好的，因為環境步驟由 implement 落地。

```text
- [ ] 建立 backend/ 骨架 → implement 執行 mkdir／驗證
```

## Bad Example

- 這個例子是壞的，因為把環境建立塞進 `/tdd-e2e-red`。

```text
呼叫 red 時順便請它 npm init
```

# Rule 2 - 標有 tdd skill 的步驟必須委派並帶齊參數

- Level: `MUST`
- 步驟文字含 `/tdd-e2e-red` 時委派該 skill，並傳：`layer`、`plan-package`、單一 Scenario ID／標題、該格實作計畫。
- 含 `/tdd-e2e-green` 或 `/tdd-e2e-refactor` 時委派對應 skill，並傳：`layer`、`plan-package`、單一 US 識別、該格實作計畫（及 green 所需之本 US Scenario／測範圍若可從 task 收斂）。
- 缺參數不得委派；應停止並回報。

## Good Example

- 這個例子是好的，因為 red 參數齊。

```text
DELEGATE /tdd-e2e-red
layer=backend
plan-package=001-photo-albums
Scenario=S-1-1 …
實作計畫=（該格巢狀條列）
```

## Bad Example

- 這個例子是壞的，因為只說「去做 red」不帶 Scenario。

```text
DELEGATE /tdd-e2e-red（無其他參數）
```

# Rule 3 - 執行順序跟 task 文件，不跳著做

- Level: `MUST`
- 單一層內從第一個未勾選 checkbox 往下依序執行；完成一個再下一個。
- 多層時依進場選定順序，完成當層可執行範圍後再進下一層。
- 不可為求快而跳過未勾的 §1／§2 直接做 §3（除非該項已勾選）。

## Good Example

- 這個例子是好的，因為先做未勾的環境項再進 Red。

```text
未勾: §2.1 → 先做完並勾選 → 再做第一個 Red
```

## Bad Example

- 這個例子是壞的，因為 §2 未做完就呼叫一排 Red。

```text
環境未勾 → 直接委派 S-1-1…S-1-5
```
