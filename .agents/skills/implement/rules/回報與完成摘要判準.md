# Rule 1 - 成功結束要有可接續摘要

- Level: `MUST`
- 本輪成功完成時必須回報：`plan-package`、執行的層別順序、各層完成與否、關鍵已勾進度（或指向 task 檔）、建議下一步（例如下一範圍或結束）。

## Good Example

- 這個例子是好的，因為範圍與進度清楚。

```text
package: 001-photo-albums
ran: backend → frontend
backend: task-backend 本輪範圍已全勾
frontend: 至 US-1 Green 完成
next: 可再 /implement 選整合，或繼續前端未勾項
```

## Bad Example

- 這個例子是壞的，因為只說「做完了」。

```text
implement 完成
```

# Rule 2 - 失敗結束要有可操作卡點

- Level: `MUST`
- 失敗／中止時必須回報：失敗發生的層與步驟（引用 task 文案或 Scenario／US）、卡點類型、子 skill 回報摘要（若有）、已保留的已勾進度、建議下一步（重試該步／先補環境／改範圍等）。

## Good Example

- 這個例子是好的，因為使用者知道怎麼續。

```text
failed: backend / S-1-2 Red
reason: 環境洞 — 無 npm test
kept: §1§2 與 S-1-1 已勾
next: 補測試腳本後再 /implement（同範圍會從 S-1-2 續）
```

## Bad Example

- 這個例子是壞的，因為失敗原因不可操作。

```text
壞掉了，你自己看 log
```
