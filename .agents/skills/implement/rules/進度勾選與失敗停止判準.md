# Rule 1 - 成功步驟必須勾選對應 checkbox

- Level: `MUST`
- 每一步親自執行或委派成功後，必須把該步在對應 `task-*.md` 的 `- [ ]` 改為 `- [x]`（或 `- [X]`）。
- 不可只在對話說完成卻不改檔；續跑以未勾項為準。

## Good Example

- 這個例子是好的，因為檔案進度與實際一致。

```md
- [x] `/tdd-e2e-red` — S-1-1 …
```

## Bad Example

- 這個例子是壞的，因為對話稱完成但 checkbox 仍空。

```md
- [ ] `/tdd-e2e-red` — S-1-1 …
（對話：這格好了）
```

# Rule 2 - 失敗立即停止，已勾保留

- Level: `MUST`
- 一般步驟失敗（含委派 skill 回報環境洞、契約衝突、超出本則邊界或無法修復的非預期結果）時，立即停止後續步驟。
- 唯一的內部修復例外是 Scenario 完成後的累積 User Story 閘門：若本則修改弄紅既有 Scenario，先由目前 Scenario Agent 留在同一脈絡修復並重跑新舊案例；這是本則尚未完成，不算可以跳過的失敗。
- 只有累積回歸無法在本則邊界內修復、顯示上游契約衝突或環境洞時，Scenario Agent 才回報失敗給 `/implement`；此時 `/implement` 停止並等待使用者決定。
- 已成功並勾選的項目保持已勾；失敗當步不勾選。
- 必須回報卡點與建議下一步，等待使用者再決定如何續跑；不可自動跳過失敗格。

## Good Example

- 這個例子是好的，因為停在失敗格且保留進度。

```text
已勾: §1、§2、S-1-1 Red
失敗: S-1-2 Red（環境洞）→ 停止，不跑後面
```

## Bad Example

- 這個例子是壞的，因為失敗後自動跳過繼續 Green。

```text
S-1-2 Red 失敗 → 跳過並開始 Green
```

# Rule 3 - Scenario Agent 不代勾；勾選是 implement 的職責

- Level: `MUST`
- Scenario Agent 回報各階段與層內全綠閘門成功後，由 `/implement` 依證據勾選對應四格；不可期待代理或 tdd skill 改 task 檔。
- User Story 完成閘門與整合完全端對端驗收由 `/implement` 親自執行，通過後自行勾選。

## Good Example

- 這個例子是好的，因為委派成功後 implement 寫回 checkbox。

```text
Scenario Agent 回報 Red、Green、Refactor、層內全綠皆成功 → implement 勾四格
```

## Bad Example

- 這個例子是壞的，因為假定 red 會自己勾 task。

```text
等 Scenario Agent 去改 task-backend.md
```
