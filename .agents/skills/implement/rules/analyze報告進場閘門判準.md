# Rule 1 - package 鎖定後必須嘗試讀取 analyze-report

- Level: `MUST`
- 在 `plan-package` 已鎖定、且尚未輸出範圍選單／開始執行任何 task 步驟之前，必須檢查 `specs/<plan-package>/analyze-report.md`。
- 若檔案**存在**：必須 READ 整份報告（至少含「問題總表」與「指標」），再依後續規則判定是否硬停。
- 若檔案**不存在**：MUST 留下可察覺警告（例如「未找到 analyze-report.md，依本輪繼續；建議先跑 `/analyze`」），然後繼續進場，不得因缺檔而強制中止。

## Good Example

- 這個例子是好的，因為有報告就讀、無報告只警告。

```text
鎖定 plan-package = 002-meeting-room-booking
→ 存在 specs/002-meeting-room-booking/analyze-report.md → READ 後再進範圍選單
```

## Bad Example

- 這個例子是壞的，因為有報告卻跳過不讀。

```text
直接輸出範圍選單，從未開啟 analyze-report.md
```

# Rule 2 - 如何判定「有嚴重發現」

- Level: `MUST`
- 同時以兩處為準（任一成立即視為有嚴重發現）：
  1. 「指標」表中「嚴重」列的數值為正整數（≥ 1）。
  2. 「問題總表」任一列的「嚴重程度」欄為 `嚴重`（或等價用詞「嚴重」）。
- 不可只掃對話摘要或憑記憶假設「上次分析過就沒問題」。
- 僅有「高／中／低」或表下註明「本輪無問題」時，不構成本規則的嚴重硬停。

## Good Example

- 這個例子是好的，因為以報告欄位判定。

```text
指標｜嚴重｜2 → 有嚴重發現
問題總表列：嚴重程度 = 嚴重 → 有嚴重發現
```

## Bad Example

- 這個例子是壞的，因為忽略指標仍當無嚴重。

```text
指標嚴重 = 1，卻說「看起來還好」直接進範圍選單
```

# Rule 3 - 有嚴重發現時必須硬停並取得明示確認

- Level: `MUST`
- 若判定有嚴重發現：必須在對話硬停，摘要列出嚴重項（編號＋摘要＋建議處理，可截前 N 項），並明確詢問使用者二擇一（或等價語意）：
  1. 先處理嚴重項（重跑點名的 skill／改來源檔）後再回來 `/implement`；或
  2. **明示仍要繼續本輪實作**（acknowledge 風險）。
- 未收到使用者回覆前，不得輸出範圍選單、不得執行任何 task checkbox。
- 僅當使用者明示「仍要繼續／proceed／忽略嚴重項繼續」等肯定語意後，才可進入範圍選單。
- 不可把「強烈建議先修」寫完就當已放行。

## Good Example

- 這個例子是好的，因為硬停等確認。

```text
偵測到嚴重 2 項（見 analyze-report.md）：
- 一致-1：…
請回覆：先修嚴重項，或「仍要繼續實作」。
（未回覆前停止）
```

## Bad Example

- 這個例子是壞的，因為有嚴重項仍直接問範圍。

```text
報告有嚴重項 → 仍輸出「這次要跑哪一種範圍？」
```
